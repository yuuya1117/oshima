# 本番構築手順（レンタルサーバー編）

エックスサーバー等のレンタルサーバー（PHP + MySQL）に、
staging サブドメインを挟んで移行する手順。

URLの正は `design_handoff_wordpress/URL移行マップ.md`、
テーマの規約は `../CLAUDE.md`、切り替え時の注意は `移行手順.md` 4-2。

---

## 全体の流れ

```
0. 準備        現行サイトの控えを取る
1. ステージング  staging.torasake.com に WordPress + テーマ
2. コンテンツ投入 ← 作業量の大半
3. 検証        全URLに200が返るか
4. 本番切替     旧HTMLを退避して差し替え
```

ステージングを使わず本番に直接入れる場合は **付録A** を見ること。
この構成なら直接でも作業を分離できる（旧HTMLが残っている間は旧サイトが出続けるため）。

---

## 0. 準備 — 現行サイトの控えを取る

あとで「1本も失っていないか」を照合するための材料。切り替え後には取れない。

- [ ] 現行サイトをクロールして全URLを一覧化（Screaming Frog 等）。URL移行マップと突き合わせる
- [ ] Search Console → 検索結果のパフォーマンス → 過去6ヶ月の**流入上位URL**をエクスポート
- [ ] Search Console → リンク → **被リンクのある上位ページ**をエクスポート
- [ ] 各ページの `<title>` / `meta description` / OGP / JSON-LD を控える
      （ブラウザで「ページのソースを表示」→ head をコピー。あとでACFに原文のまま入れる）
- [ ] `/uploads/` 配下のファイル一覧を控える（FTPでフォルダごとダウンロードしておくと安心）

## 1. ステージング構築

### 1-1. サブドメインを作る

サーバーパネル → **ドメイン設定** → サブドメイン追加 → `staging`
（エックスサーバー以外でも「サブドメイン設定」に相当する項目がある）

無料SSLも一緒に有効化しておく。反映に数十分かかることがある。

### 1-2. WordPress を入れる

サーバーパネル → **WordPress簡単インストール** → staging.torasake.com を選択

- サイトURL: `https://staging.torasake.com`
- データベース: 自動生成でよい
- **PHPバージョンは 8.1 以上**（サーバーパネルの「PHP Ver.切替」で確認）

### 1-3. 検索に載らないようにする（重要）

ステージングがインデックスされると本番と重複コンテンツになる。**2重でかける。**

- [ ] 管理画面 → 設定 → 表示設定 → 「検索エンジンでの表示」にチェック
- [ ] サーバーパネル → **アクセス制限**（Basic認証）を staging に設定

### 1-4. テーマを入れる

このリポジトリの `themes/torasake` ディレクトリを、サーバーの
`/staging.torasake.com/public_html/wp-content/themes/` に丸ごとアップロードする。

- GitHubの緑の「Code」→「Download ZIP」で落として、`themes/torasake` だけを取り出す
- FTPソフト（FileZilla, Cyberduck）かサーバーのファイルマネージャでアップロード
- **`themes/torasake/` の中身ではなく、`torasake` フォルダごと**置くこと

### 1-5. カスタムフィールドのプラグインを入れる（必須）

このテーマは **repeater 13箇所・gallery 1箇所・オプションページ 1箇所**を使う。
ACF の**無料版では動かない**（これらは有料版限定の機能のため）。
選択肢は2つ。

**A. Secure Custom Fields（無料・まずこちらを試す）**

WordPress.org が2024年10月に ACF をフォークした公式プラグイン。
repeater を含む PRO 機能が無料で入っている。ACFの直接フォークなので
関数名もDB構造も同じで、テーマの改造は不要。

管理画面 → プラグイン → 新規追加 → 「Secure Custom Fields」で検索 → 有効化

**B. ACF PRO（有料・年$49〜）**

https://www.advancedcustomfields.com/pro/ で購入 → zip をダウンロード
→ プラグイン → 新規追加 → プラグインのアップロード → 有効化 → ライセンスキー入力

**どちらでもよい。判定は次の1点。**

酒蔵の新規追加画面を開いて「出展銘柄」の**［銘柄を追加］ボタンが出れば成功**。
出なければ repeater が効いていないので、もう一方を試す。

プラグインが無い状態だと管理画面に赤い警告が出る（テーマが出している）。
白画面にはならないが、入力欄は一切出ない。

### 1-6. テーマを有効化

管理画面 → 外観 → テーマ → **TORASAKE** を有効化。

有効化時に以下が自動で入る（冪等なので何度有効化しても壊れない）。

- 固定ページ: トップページ / お知らせ / 過去のイベント / 協賛について
- 表示設定: フロントページと投稿ページの割り当て
- 初期ターム: 開催回2件、お知らせカテゴリ3件
- リライトルール

続けて **設定 → パーマリンク設定 → 変更を保存**（何も変えずに押すだけ）。
リライトルールの再書き出しのため。これを忘れると404が出る。

### 1-7. 動作確認

- [ ] `https://staging.torasake.com/` が表示される（まだ「次回準備中」でOK）
- [ ] 管理画面の左メニューに 酒蔵 / イベント / 過去開催 / ブログ / 協賛企業 がある
- [ ] 酒蔵の編集画面にACFの項目（銘柄・ロゴ・出展銘柄など）が出ている
      → 出ていなければ ACF PRO が有効化されていない

## 2. コンテンツ投入

ここが作業量の大半。**スラッグだけは絶対に間違えないこと**（URLが変わる＝SEOを失う）。

### 2-0. インポートで一気に入れる（推奨・手入力の代わり）

`import/torasake-content.xml` を読み込むと、次が一度に入る。
手入力だと半日かかるところが10分程度になり、**スラッグの打ち間違いも起きない**。

| 中身 | 件数 | 状態 |
|---|---|---|
| 画像 | 37 | 本番 `/uploads/` からダウンロードして取り込む |
| 酒蔵 | 33 | 公開。スラッグ・蔵名・銘柄・都道府県・開催回・アイキャッチ入り |
| お知らせ | 5 | 開催報告1件は本文入りで公開。**残り4件は下書き**（後述） |
| イベント | 2 | mini は券種・開催概要・指標カードまで投入済み |
| 過去開催 | 1 | 統計カード・開催概要・本文入り |

**手順**

1. **先にテーマを有効化しておく**（1-6 まで済ませる）
   未登録の投稿タイプはインポーターに無視されるため、テーマが無効だと
   酒蔵もイベントも1件も入らない
2. 管理画面 → ツール → インポート → 「WordPress」の**今すぐインストール**
3. 「インポーターの実行」→ `import/torasake-content.xml` を選択
4. 投稿者は既存ユーザーに割り当てる
5. **「添付ファイルをダウンロードしてインポートする」に必ずチェック**
   （外すと画像が1枚も入らない）
6. 実行。画像37件のダウンロードがあるので数分かかる

**インポート後に手でやること（3つだけ）**

- [ ] **イベント「TORASAKE mini」の参加酒蔵を選ぶ**
      WordPressのインポーターは投稿IDを振り直すが relationship のメタは
      振り直さないため、壊れたIDを入れるくらいなら空にしてある。
      編集画面で下の10蔵を選ぶ:
      成龍酒造 / 大信州酒造 / 豊国酒造 / 高千代酒造 / 丸石醸造 /
      農口尚彦研究所 / 豊島屋酒造 / 富美菊酒造 / 小野酒造店 / 笑四季酒造
- [ ] **お知らせ4件の本文を入れて公開する**
      参照HTMLに抜粋しか無いため下書きで入っている。現行サイトの
      各記事から本文をコピーして貼り、公開に切り替える。
      **下書きのままだとそのURLが404になり、既存URLを1本失う**
- [ ] 蔵の物語・タグライン・出展銘柄の詳細を埋める（参照HTMLに無いデータ）

インポートファイルを作り直したいときは `python3 tools/make-wxr.py`。
検証は `python3 tools/check-wxr.py`（スラッグが移行マップと一致するか等を見る）。

## 3. 検証

ステージングのURLで、本番相当の全パスに200が返るか確認する。

```sh
sh tools/check-urls.sh https://staging.torasake.com "" USER:PASS
```

Basic認証をかけているので `-u USER:PASS` が要る。

- [ ] 上記すべて 200
- [ ] 酒蔵一覧の検索・都道府県・開催回フィルタが動く
- [ ] トップのカウントダウンが動く
- [ ] 酒蔵一覧・詳細に**価格が出ていない**
- [ ] Peatixリンクに `?utm_source=hp` が付いている
- [ ] スマホ幅で崩れない

## 4. 本番切り替え

### 4-1. バックアップ（切り戻し用）

- [ ] 本番の全ファイルをFTPでダウンロード（特に `/uploads/` と全 `.html`）
- [ ] サーバーパネルの**自動バックアップ**からも復元できるか確認しておく

### 4-2. 本番にWordPressを入れる

ステージングをそのまま複製するのが確実。

- **All-in-One WP Migration** などのプラグインでエクスポート → 本番にインポート
- または本番に新規インストールし、同じ手順（1-4〜1-6）＋コンテンツを再投入

いずれの場合も本番側で:

- [ ] 設定 → 一般 → WordPressアドレス / サイトアドレスが `https://torasake.com` になっているか
- [ ] 設定 → 表示設定 → 「検索エンジンでの表示」の**チェックを外す**（外し忘れが一番多い事故）
- [ ] 設定 → パーマリンク設定 → 変更を保存

### 4-3. 旧HTMLを退避 ★ここを忘れると方式Aが壊れる

WordPressの `.htaccess` は実ファイルがあればWPに渡さない。
旧 `.html` が残っていると、テーマのリライトが発火せず古いHTMLが出続ける（エラーは出ない）。

| パス | 扱い |
|---|---|

# 付録A. ステージングを使わず本番に直接入れる

サブドメインを立てずに torasake.com へ直接 WordPress を入れるルート。

## なぜ直接でも作業を分離できるのか

WordPress の `.htaccess` は**実ファイルがあればWPに渡さない**。
つまり `index.html` と `/news/*.html` が残っている限り、WordPress を
インストールしても**旧サイトがそのまま出続ける。**

```
WPインストール直後のドキュメントルート

  index.html      ← これが出る（DirectoryIndex で .html が .php より先）
  index.php       ← WordPress。まだ誰も見ない
  news/*.html     ← これが出る
  uploads/        ← そのまま
  wp-admin/       ← 管理画面は使える
  wp-content/
```

だから「**入れる**」と「**切り替える**」を分けられる。

- 入れる … 旧サイトは無傷。管理画面で作り込める
- 切り替える … 旧HTMLを移すだけ
- 戻す … 旧HTMLを戻すだけ（1分）

**唯一の条件はバックアップを取ること。** これさえあれば失敗しても戻せる。

## 作業中に何が見えるか

切り替え前でも、**新URLはもう見える**。ここで大半の確認ができる。

| URL | 切り替え前の状態 |
|---|---|
| `/` `/news/` `/news/*.html` `/past/` | 旧サイト（静的HTML） |
| `/breweries/` `/breweries/*.html` | **新サイト（WordPress）** |
| `/events/` `/events/*.html` `/blog/` `/sponsors/` | **新サイト（WordPress）** |
| `/wp-admin/` | **管理画面** |
| `/index.php` | **新トップページ**（切り替え前に見るための抜け道） |

トップの見た目を切り替え前に確認したいときは `https://torasake.com/index.php` を開く。

## A-0. バックアップ（これだけは飛ばさない）

ここを飛ばすと「失敗してもいい」が成立しなくなる。

- [ ] **FTPでドキュメントルートを丸ごとダウンロード**
      特に `index.html` / `news/` / `past/` / `uploads/` / `.htaccess`
- [ ] `.htaccess` は単体でもコピーを取る（WPが書き換えるため）
- [ ] サーバーパネルの**自動バックアップ**が有効か、復元できるか確認
- [ ] ダウンロードしたフォルダを別名で保存（例 `torasake-backup-20260929`）

`.htaccess` は隠しファイルなのでFTPソフトの設定で「隠しファイルを表示」にしないと見えない。

## A-1. データベースを作る

サーバーパネル → **MySQL設定** → MySQLデータベース追加

- データベース名: 任意（例 `torasake_wp`）
- 文字コード: **UTF-8**

続けて **MySQLユーザ追加** → 作ったDBに**アクセス権を付与**する。

ここで決めた「DB名 / ユーザ名 / パスワード / ホスト名」を控える。ホスト名は
MySQL設定画面に表示されている（`localhost` ではないことが多い）。

## A-2. WordPress を手動でインストール

**「WordPress簡単インストール」は使わない。** ドキュメントルートが空でないため
挙動が読みにくく、既存ファイルを消す選択肢が出ることがある。手動なら確実。

1. https://ja.wordpress.org/download/ から日本語版をダウンロードして解凍
2. 解凍した `wordpress` フォルダの**中身**を、ドキュメントルートにアップロード
   - `wp-admin/` `wp-includes/` `wp-content/` と、直下の `.php` ファイル群
   - **`index.html` とはファイル名が違うので上書きされない**
   - `uploads/` も `news/` も触らない
3. `https://torasake.com/wp-admin/install.php` を開く
4. A-1で控えたDB情報を入力
5. サイトのタイトル・管理ユーザ・パスワードを設定してインストール

この時点で `https://torasake.com/` を開いても**まだ旧サイトが出る**。正常。

- [ ] `https://torasake.com/wp-admin/` にログインできる
- [ ] `https://torasake.com/` が旧サイトのまま出る

**PHPバージョンが 8.1 未満ならここで上げる**（サーバーパネル → PHP Ver.切替）。

## A-3. テーマとプラグイン

手順書の 1-4 / 1-5 / 1-6 と同じ。

1. `themes/torasake` を `wp-content/themes/` にアップロード
2. **Secure Custom Fields**（無料）を有効化。出展銘柄の［銘柄を追加］が出るか確認
3. 外観 → テーマ → TORASAKE を有効化
4. **設定 → パーマリンク設定 → 変更を保存**

パーマリンクを保存すると WordPress が `.htaccess` に自分のブロックを追記する。
既存の記述は `# BEGIN WordPress` の外にあるので消えないが、
保存後に `.htaccess` を開いて元の記述が残っているか目視する。

- [ ] `https://torasake.com/breweries/` が開く（まだ0件でよい）
- [ ] `https://torasake.com/` はまだ旧サイト

## A-4. コンテンツを入れる

2-0 のインポートをそのまま実行する。

- [ ] テーマ有効化済みであることを確認（未登録の投稿タイプは無視される）
- [ ] ツール → インポート → WordPress → `import/torasake-content.xml`
- [ ] **「添付ファイルをダウンロードしてインポートする」にチェック**

インポート後の手作業3つ（イベントの参加酒蔵10蔵を選ぶ／お知らせ4件の本文を
入れて公開する／蔵の物語等を埋める）も 2-0 のとおり。

**お知らせ4件は必ず公開まで済ませる。** 下書きのまま切り替えると
そのURLが404になり、既存URLを1本失う。

## A-5. 切り替え前の確認

旧サイトはまだ生きているので、ここは落ち着いて見られる。

```sh
sh tools/check-urls.sh https://torasake.com before
```

手元にリポジトリが無ければブラウザで1本ずつ開いてもよい。

- [ ] 上記すべて 200
- [ ] `/index.php` で新トップの見た目を確認（KV・チケット・参加酒蔵）
- [ ] 酒蔵一覧の検索・都道府県・開催回フィルタが動く
- [ ] 酒蔵ページに**価格が出ていない**
- [ ] Peatixリンクに `?utm_source=hp` が付いている
- [ ] スマホ幅で崩れない

ここで気になるところがあれば、**まだ旧サイトが出ている間に**直す。

## A-6. 切り替え（ここから数分だけ本番が動く）

旧HTMLを移す。**削除ではなく移動**。戻せることが大事。

FTPソフトなら、ドキュメントルートの外（公開されない場所）に
`_legacy_html` フォルダを作って、そこへドラッグで移す。

| 移すもの | 残すもの |
|---|---|
| `index.html` | `uploads/` ← **絶対に動かさない** |
| `news/` 内の `.html` 全部 | `wp-*` |
| `past/index.html` | `.htaccess` |

SSHが使えるなら:

```sh
cd /path/to/torasake.com/public_html
mkdir -p ../_legacy_html/news ../_legacy_html/past
mv index.html            ../_legacy_html/
mv news/*.html           ../_legacy_html/news/
mv past/index.html       ../_legacy_html/past/
# uploads/ には触れない
```

移した直後から `https://torasake.com/` が新サイトになる。

## A-7. 切り替え後の確認

```sh
sh tools/check-urls.sh https://torasake.com
```

既存URL10本＋新URL8本をまとめて見る。**1本でも 200 でなければ切り替えを戻す**（A-8）。

- [ ] すべて 200（301なら最終到達先が200か）
- [ ] 画像が表示される（`/uploads/` を動かしていないか）
- [ ] 設定 → 表示設定 → 「検索エンジンでの表示」に**チェックが入っていない**
- [ ] Search Console でサイトマップを再送信

## A-8. 戻し方（1分）

問題が出たら、移したファイルを戻すだけ。WordPress は入ったままだが、
実ファイルが優先されるので**また見えなくなる**。

```sh
cd /path/to/torasake.com/public_html
mv ../_legacy_html/index.html      .
mv ../_legacy_html/news/*.html     news/
mv ../_legacy_html/past/index.html past/
```

FTPなら `_legacy_html` から元の場所へドラッグで戻す。

これで旧サイトに戻る。落ち着いてから A-5 からやり直せる。

**WordPress ごと消したい場合**は、`.htaccess` をバックアップから戻し、
`wp-admin/` `wp-includes/` `wp-content/` と直下の `wp-*.php` `index.php`
`xmlrpc.php` `license.txt` `readme.html` を削除する。DBはサーバーパネルから削除。

## 直接ルートで気をつける点

| 点 | 内容 |
|---|---|
| `.htaccess` | WPが書き換える。事前にコピーを取り、保存後に元の記述が残っているか見る |
| `robots.txt` / `sitemap.xml` | 実ファイルで置いてあるならWPの仮想版より優先される。中身を見直す |
| 「検索エンジンでの表示」 | この手順では**最初から最後までチェックしない**。旧サイトが出ている間は新URLしか露出せず、新URLには失う順位が無いため。チェックを入れて外し忘れると全ページが検索から消えるので、その事故を避ける |
| 作業時間 | A-6 の切り替えは数分で終わる。A-2〜A-5 は旧サイトが生きたまま何時間かけてもよい |
| Hello world | WPの初期投稿とサンプルページは削除しておく |

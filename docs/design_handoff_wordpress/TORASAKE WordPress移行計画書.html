1. 目的とゴール

現状、torasake.comは静的HTMLで構築されている。長期運営・継続開催イベントとして育てていくため、以下を目的にWordPress化する。

  • 酒蔵・イベント・ニュース・スポンサー・過去開催情報を、開発者を介さず継続的に更新できるようにする
  • 1日1,000人以上の来場を狙う規模のイベント告知に耐える運用体制（更新頻度・SEO・表示速度）を整える
  • 年1〜2回の大型イベント（出展30蔵以上）と、小規模なミニイベント（300〜500名・10蔵前後）の両方を同じ仕組みで運用できるようにする（開催頻度は未確定のため「月次」等の断定した表現はサイト上で使わない）

5. SEO・既存資産の引き継ぎ（最重要）

既存URLを変えないことを最優先要件とする。現行サイトはすでにインデックスされており、アクセス資産を失うリスクは許容しない。.html 付きURLをそのまま正規URLとして維持する「方式A」を採用。リライトルールと全URLリストは同梱 URL移行マップ.md を参照（実装前に必読）。
  • 投稿スラッグは現行ファイル名と完全一致させる。日本語スラッグ2本（2026-06-27-当日券 / 2026-05-21-開催決定）は生の日本語で入力する
  • 現行トップのアンカー（#pairing #floormap #faq 等）は外部から参照されている。これらを残すため、6/27のLPを /past/torasake-2026/ に丸ごと保存してからトップをv6に差し替える
  • 画像は /uploads/ の旧パスを生かす（メディアライブラリに取り込むと /wp-content/uploads/ に変わり、画像検索流入とOGPキャッシュが切れる）
  • 各ページの <title> / meta description / OGP / 構造化データ（Organization・BreadcrumbList）は現行HTMLの記述をそのまま移植する
  • sitemap.xml / robots.txt はSEOプラグイン側の自動生成に切り替え、公開直後にSearch Consoleへ再送信してカバレッジを1週間監視

6. スケジュール

目安の締切：2026年10月16日（TORASAKE mini 開催日）。チケットは既に発売済なので、告知トップ（front-page）を最優先で公開し、酒蔵一覧・ニュースは後続とする二段階リリースを推奨する。表示逸脱を避けるため、公開切替はステージングで全URLの200確認を済ませてから行うこと。

Day 1｜設計確定

CPT/ACF/タクソノミー確定、ステージング構築、URL移行マップのリライトルールを先に実装して既存URLが200を返すことを確認

Day 2-3｜テーマ実装（トップ・酒蔵）

front-page（v6）、archive/single-brewery を実装。検索・フィルタJSをWP_Query＋REST/Ajaxに置換

Day 4-5｜テーマ実装（イベント・ニュース・過去開催・スポンサー）

残り全テンプレート実装。6/27のLPを /past/torasake-2026/ として保存。管理画面の入力UIを運用担当が実際に試す

Day 6｜コンテンツ移行

酒蔴33件・ニュース5本・過去開催をCPTへ流し込み。スラッグを既存ファイル名と一致させる。画像最適化

Day 7｜QA・SEO・公開

全URLの200/301確認、旧 /uploads/ 画像の疎通確認、表示速度計測、モバイル確認、構造化データ検証、サイトマップ再送信

7. 今後の運用に向けて

  • 年1〜2回の大型イベント（30蔵以上）については、開催回タクソノミーで酒蔵の出展履歴を蓄積し、回を重ねるごとに「参加酒蔵一覧」の資産価値を高める設計にする
  • ミニイベントは event CPTの軽量入力（テーマ・会場・少数蔵・券種）で運用者が自走できるようにする。新しい回を公開したらトップが自動でその告知に切り替わる設計とし、終了した回は past_event へ移す
  • 1,000人/日規模の集客を目指すフェーズでは、公開後の表示速度・サーバー負荷のモニタリングを継続する

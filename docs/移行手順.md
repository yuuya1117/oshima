# 移行手順（方式A）

`design_handoff_wordpress/URL移行マップ.md` の実装側メモ。
URLの正は常に移行マップ。ここはテーマ側で何をどう受けているかの対応表。

## 1. テーマ有効化

有効化すると `after_switch_theme` で以下が走る（すべて冪等・既存設定は上書きしない）。

| 処理 | 内容 |
|---|---|
| パーマリンク構造 | 未設定なら `/%postname%/` にする |
| 固定ページ | `front`（トップ受け皿）・`news`（投稿ページ）・`past`・`sponsors` を作成 |
| 表示設定 | `show_on_front=page` / `page_on_front=front` / `page_for_posts=news` |
| 初期ターム | `event_edition`: `torasake-2026` `torasake-mini-2026`／`category`: `report` `info` `guide` |
| リライト | ルール書き出し（`flush_rewrite_rules`） |

`page_for_posts` が既に設定済みの環境では表示設定に触れない。手で設定する場合は
「設定 > 表示設定」で投稿ページを「お知らせ」にすること。

## 2. URL 対応表

| URL | 受け口 | 実装 |
|---|---|---|
| `/` | `front-page.php` | 固定ページ front を front_page に設定 |
| `/index.html` | 301 → `/` | `torasake_redirect_legacy_index()` |
| `/news/` | `home.php` | `page_for_posts` |
| `/news/index.html` | 301 → `/news/` | 同上 |
| `/news/{slug}.html` | `single.php` | `add_rewrite_rule('^news/([^/]+)\.html$', ...)` |
| `/past/` | 固定ページ past | ─ |
| `/past/index.html` | 301 → `/past/` | 同上 |
| `/past/{slug}/` | `single-past_event.php` | `add_rewrite_rule('^past/([^/]+)/?$', ...)` |
| `/events/` | `archive-event.php` | `add_rewrite_rule('^events/?$', ...)` |
| `/events/{slug}.html` | `single-event.php` | `add_rewrite_rule('^events/([^/]+)\.html$', ...)` |
| `/sponsors/` | `page-sponsors.php` | 固定ページ + テンプレート割り当て |
| `/breweries/` | `archive-brewery.php` | `add_rewrite_rule('^breweries/?$', ...)` |
| `/breweries/{slug}.html` | `single-brewery.php` | `add_rewrite_rule('^breweries/([^/]+)\.html$', ...)` |
| `/blog/` | `archive-blog_post.php` | `add_rewrite_rule('^blog/?$', ...)` |
| `/blog/{slug}/` | `single-blog_post.php` | `add_rewrite_rule('^blog/([^/]+)/?$', ...)` |
| `/uploads/*` | 実ディレクトリ | 下記3章 |

パーマリンクの出力側も `.html` に揃えてある（`post_link` / `post_type_link` フィルタ）。
これを外すと本文中や一覧のリンクが `/news/{slug}/` になり、方式Aが崩れる。

`redirect_canonical` は `post` / `brewery` / `event` の単体ページで無効化してある。

一覧を持つ CPT（`brewery` / `event` / `blog_post`）は `rewrite => false` のまま
`has_archive` を真値にしてある。これを `false` に戻すと `is_post_type_archive` が
立たず、`/breweries/` などが `home.php` になる。詳細は CLAUDE.md の 5 番。
WordPress の正規化が `.html` を `/` 付きに飛ばそうとするため。

## 3. 投稿スラッグ（現行ファイル名と完全一致させる）

```
2026-07-03-event-report
2026-06-27-当日券          ← 生の日本語で入力する
2026-05-28-matching
2026-05-25-event-system
2026-05-21-開催決定        ← 生の日本語で入力する
```

日本語スラッグをパーセントエンコードして貼らないこと。WordPress は `post_name` を
内部でエンコードして保持し、`sanitize_title_for_query()` が照合時に再エンコードするので、
管理画面には日本語のまま入れれば通る。

## 4. 画像URLの維持

現行の画像は `/uploads/` 直下。メディアライブラリに取り込むと
`/wp-content/uploads/YYYY/MM/` に変わり、画像検索の流入とOGPキャッシュが切れる。

**`/uploads/` は実ディレクトリのまま残す。** WordPress の `.htaccess` は
`RewriteCond %{REQUEST_FILENAME} !-f` を持つので、実ファイルはWPを経由せず配信される。
ドキュメントルート直下に `uploads/` を置いたままにすれば追加設定は要らない。

Nginx の場合は WP に回す前に実ファイルを返す設定になっているか確認する。

```nginx
location ^~ /uploads/ {
    try_files $uri =404;
    access_log off;
    expires 30d;
}
```

特に外部にキャッシュされている次の2点は必ず疎通を確認する。
- `/uploads/keyvisual.jpg` — 現行トップのOGP画像
- `/uploads/staff.jpg` — `/past/` のOGP画像

蔵ロゴ等をメディアライブラリからも使いたい場合は、**コピーを取り込む**（元は消さない）。

## 6. トップページのアンカー（移行マップ 2章）

現行 `/` は 6/27 イベント単体のLPで、`#hero` `#breweries` `#how-to-enjoy` `#pairing`
`#howto` `#floormap` `#access` `#faq` が外部から参照されている。
アンカーはサーバ側でリダイレクトできない。

確定版の v6 トップは `#hero` `#breweries` `#tickets` `#archive` `#news` `#lead` `#outline` `#food`
を持つので、`#hero` と `#breweries` は生きる。残りは着地するだけになるため、
移行マップの推奨どおり **6/27 LP を `/past/torasake-2026/` に丸ごと保存**し、
トップに「過去の開催回はこちら」の導線（アーカイブセクション）を置いてある。

## 7. 参照HTMLが無い2ページについて

`archive-blog_post.php`（/blog/）と `archive-event.php`（/events/）は、
一覧のデザインがハンドオフに含まれていない（記事単体・イベント単体のみ）。

ゼロから作らず、**他の参照で確定している組み方を組み合わせて確定させてある。**

| ページ | 流用元（すべて確定値のまま） |
|---|---|
| 両方 | ベース（nav / page-hero / footer）… `news-archive.html` |
| /blog/ | カード構造・hoverズーム … `top-page.html` の `.news-card` |
| /blog/ | 金のカテゴリバッジ … `blog-single-template.html` の `.article-cat` |
| /events/ | 開催予定の紺カード … `top-page.html` の `.arch` |
| /events/ | 終了した回の行 … `brewery-style.css` の `.eh-row` |
| /events/ | セクションラベルの左右罫線 … `top-page.html` の `.s-label` |

新しく決めたのは構成だけ（ブログ＝カードの列数と動画の再生マーク、
イベント＝開催予定を大きく1件・終了分を下に行で並べる）。

確定済みCSSは一切書き換えていない。追加分は
`assets/css/blog-archive.css` / `event-archive.css` に分けてあり、
`news-archive.css` と2枚重ねで読み込む。

## 8. 参照HTMLの `.tpl-flag` について

`event-single-template.html` と `blog-single-template.html` には
「テンプレート — 内容を差し替えてください」という付箋（`.tpl-flag`）が入っている。
これは差し替え前提の目印なので、テンプレートでは出力していない。
CSS は逐語移植の方針に従って定義だけ残してある（どこからも使われない）。

検査する。ステージングに上げる前のセルフチェック用。詳しくは `tests/README.md`。
